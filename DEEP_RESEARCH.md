# S21 wireless and USB suite: research and engineering audit

Research date: 2026-11-06. This is an audit, not a claim that these features are implemented or tested end to end. The checked Stryker source is 7590566f05e6367602d1d18771017da0c613ef37 plus local fork edits. Wifite2 source: 43c4d2c520e45cfb828a430741b915ca4f5d7128; OneShot-Extended: bd4e59d79105e832c30bb47a3bd094a6a3821fa2; android-usb-script: 68a2503dfd9fb79b4aa96dcf0a64ab65c0085ebc.

## Evidence from this phone

- Exynos 2100, `dhd_bcm4375`, Floppy kernel `5.4.304-Floppy-v1.1.2-KN-g1ab642aefd31`; ROM reports SM-S947B because it is a port. Model strings are not sufficient for hardware verification.
- Existing module mounts firmware SHA-256 `43977f74b2f6f3f349a9dce7ab73cec2b8c289a31b802293b32d37ab69d0bf68`, identical to author's archived v1.6/v1.6.1. The active mount is visible in PID 1 mountinfo. This does not prove the running chip's firmware provenance after every driver reset.
- Actual passive capture: channel 6 under permissive and temporarily enforcing; channel 36 under permissive. Monitor enable and disarm reported interface types 803 and 1 respectively. These do not prove injection or a complete handshake capture.
- The present module explicitly switches SELinux to permissive at boot. A short enforcing test succeeded for capture, but unrelated Samsung vendor-service denials were observed. Enforcing boot and broader ROM functionality were not verified.
- `/sys/class/udc` contains `10e00000.usb` and `dummy_udc.0`; vendor gadget `g1` is currently bound to the physical controller. Config reports CONFIG_USB_CONFIGFS, CONFIG_USB_CONFIGFS_F_HID, CONFIG_USB_CONFIGFS_RNDIS and CONFIG_USB_CONFIGFS_MASS_STORAGE enabled. Host HID operation has not been tested.
- On the inspected phone Android-side system and Termux paths lacked airodump-ng and aireplay-ng; Debian Stryker includes Aircrack-ng 1.7 and iw 6.9. The native nexutil from author's ZIP runs as root. No fresh binary should be assumed to work merely because its ELF architecture is arm64.

## What the kernel change actually does

PR 10: https://github.com/FlopKernel-Series/flop_exynos2100_kernel/pull/10 . The custom firmware implements monitor mode and firmware ioctls; the driver mirrors successful commands into netdevice radiotap type. Standard channel requests are translated into Broadcom chanspec; the injection path queues raw socket frames for a firmware ioctl. The firmware's monitor query is documented in the patch as unreliable, so a successful command alone is insufficient verification. The patch guards certain channel-setting cross-band changes. It does not prove that every direct firmware ioctl or generic hopping tool is safe; no assumption of 6 GHz support should follow from channel encodings.

Use the author's sequence: disable Android Wi-Fi, bring interface up, select channel, arm with 0x613 value 2. For band change, disarm with 0x613 value 0, select the other band's channel, rearm. Verify actual interface and capture state and fail with recovery when uncertain. User previously confirmed g and s forms equivalent for this firmware; choose author's documented g form. Nexutil's output/exit code cannot by itself guarantee a successful operation.

## Concrete code audit findings

1. **Mode detection can mistake failure for managed state.** `MonitorManager.listInterfaces()` runs `iw` in the fork's chroot; empty output from missing `iw`, an unmounted rootfs, or a failed command is indistinguishable from no monitor interface. `disableMonitorMode()` can consequently consider disarm successful and clear pending recovery. Use explicit UNKNOWN / MANAGED / MONITOR / ABSENT states, independent sysfs/netlink checks, distinguish command failures, and retain pending recovery until verified. Relevant file: `app/src/main/java/com/zalexdev/stryker/utils/MonitorManager.java`.
2. **Rootless/startup and Wi-Fi recovery are inconsistent.** MainActivity turns Wi-Fi off as soon as the app starts; monitor recovery then records the already-disabled state. The 'restore prior state' code cannot restore the state from before launch. Startup also can interrupt first-time downloads and requires an asynchronous root grant. Define whether restore is on operation exit or app exit and persist the original state before any change; avoid taking a lock or restoring state owned by someone else. User explicitly wants automatic disable on open.
3. **Band state is not authoritative.** Current fork stores the last selected channel in preferences, which may go stale after crash, reboot, external tools, hopping or firmware reset. The fork re-arms only when it knows a cross-band change. Fail safely on unknown state and reconcile with observed channel; prevent another tool from independently hopping across bands. Validate each change by observed behavior, not only command exit.
4. **Custom command behavior is inconsistent.** The wlan0 disable branch forces nexutil while enabling can use user-defined commands. Avoid applying BCM behavior solely based on interface name or overwriting user choices; select a capability-based backend and keep enable/disable paired.
5. **The fork is not isolated at the data level.** Core.guestShare() still uses `/sdcard/Stryker`, and Wifi.java/WiFIAdapter.java delete fixed `handshake*`/`handshakenow*` patterns. Both original and fork can access the same output tree. Concurrent sessions can delete or consume one another's temporary files. Use unique app/session directories, atomic result publication, explicit owned PIDs and scoped cleanup. The current package and Linux rootfs names alone are not sufficient isolation.
6. **Host/chroot tool switch is architectural, not a path substitution.** Wifi.java and WiFIAdapter.java construct `AdvancedProcess(..., true)`, use guest paths and share mappings, parse CSV and output, and stop with chroot `pkill` patterns. Running native tools requires a host executor, verified binaries/libraries, explicit result path translation, cancellation by process ownership, and avoiding blanket pkill. `AdvancedProcess` launches during construction, so callbacks and configuration can race; audit before reusing it for long-running jobs.
7. **Capture result needs independent validation.** Airodump progress text and an existing CSV do not prove a usable handshake. Check capture completeness, flush/close before parsing, and distinguish capture observed from cryptographic material validated. Keep capture data private by default and export explicitly.
8. **USB gadget restoration can break ADB.** `UsbGadgetController.bind()` unbinds `/config/usb_gadget/g1/UDC`; `unbind()` selects a discovered controller instead of storing the vendor gadget's original binding, suppresses errors with `|| true`, and may report success without verifying. On this phone the real and dummy UDC both exist. Save and verify exact original binding/configuration; implement rollback and timeout; verify Android USB service behavior. Do not test unbinding over the only ADB connection without an independent recovery method. `chmodHidNodes()` uses 0666; scope access instead of leaving HID nodes world writable.
9. **Packaged firmware/SELinux:** author's module disables `bcm_mon_boot` during install, while its model guard refuses the S26-like reported model. On this ROM that combination can disable the working mount. Do not install it unchanged. Firmware bind labels differ from surrounding vendor files; collect actual AVC denials during a controlled boot and use the narrowest working policy. A file itself is not a SELinux permissive domain.
10. **Fork update and deployment:** existing module does not install the fork. APK uses a separate application ID and debug signing; module design must handle signing, upgrade, uninstall, user data, root grant, dependencies, atomic install and launch. The existing fork must not accidentally receive an upstream Stryker update or modify the original package. Audit OTA updater and rootfs scripts.

## External tool comparison and implications

- Aircrack-ng https://github.com/aircrack-ng/aircrack-ng is the existing capture/injection foundation. Termux's historical Android recipe is archived and uses dynamic libraries (libnl, libpcap, OpenSSL and C++ runtime), so copying only one binary to `/system/bin` is not a verified deployment. https://github.com/termux/termux-root-packages/blob/master/packages/aircrack-ng/build.sh . Use a maintained source/package, pin version and licenses, and validate Bionic ABI, loader paths and SELinux contexts on-device.
- Wifite2 https://github.com/derv82/wifite2 is an orchestrator using airmon and related tools. It assumes a Linux-like toolchain and has its own interface/process lifecycle. Treat it as a managed optional backend and do not let it fight the app over wlan0, disable channel guard, or kill unrelated Android services.
- OneShot-Extended https://github.com/chkndrp/OneShot-Extended explicitly says monitor mode is not required; it uses wpa_supplicant and recommends avoiding the generic kill option on Android. It needs a managed/station-capable WPS workflow and separate ownership of radio state, rather than running under an already-armed capture session. Its requirements and licensed source must be tracked.
- Android USB gadget tooling https://github.com/Netdex/android-usb-script and Linux configfs documentation https://docs.kernel.org/usb/gadget_configfs.html describe UDC binding and HID prerequisites. A kernel option and a UDC are evidence of potential support, not proof that switching gadgets is safe on this ROM.
- Kernel PR adds BNEP. Author's old module Bluetooth helper stops Android Bluetooth, assumes a particular chroot, UART and rfkill index. Neither the presence of BNEP nor a helper script proves this ROM can hand off and restore Bluetooth safely. Preserve Android settings and discover hardware rather than relying on fixed rfkill indices.

## Proposed implementation and validation order

A. Make capture directories unique and isolate OTA/uninstall/cleanup. Introduce tri-state hardware detection and one serialized radio owner, with persistent crash recovery, before adding features.
B. Build and validate Android-native tools with pinned dependencies and provenance; add host execution and independent capture verification. Keep old chroot execution behind a clearly named compatibility path until native behavior is proven.
C. Test start, capture, stop and Wi-Fi restoration with Wi-Fi initially on/off; same-band change; guarded cross-band rearm both directions; interruption and failed binary; external process conflict. Record firmware and kernel hashes, tool versions, state and error, not unrelated network contents.
D. Integrate OneShot-Extended and Wifite as optional workflows with mutually exclusive radio ownership and explicit dependency checks. Do not claim all features work until end-to-end checked.
E. Rework USB apply/rollback preserving the original physical UDC; test host recognition with independent recovery and without blanket permissions. Bluetooth requires a separate reversible handoff test.
F. Build a KernelSU package with hardware checks compatible with model-spoofing, safe installation and rollback; only replace the existing firmware mount after success is verified. Test enforcing boot and actual AVCs separately from monitor capture.
G. Re-run Android build, unit tests for state machines and parsers, source licensing review, and device tests. Maintain a capability matrix with Verified / Unverified / Unavailable labels.
